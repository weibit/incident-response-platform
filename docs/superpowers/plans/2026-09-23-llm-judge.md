# LLM-as-Judge Evaluation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Score every completed incident — four deterministic facts the workflow already computes and discards, plus one judged score for whether the RCA actually follows from its cited evidence.

**Architecture:** A separate `judge` service consumes the two terminal domain events from Kafka, reads final state from PostgreSQL, and writes scores to the incident's first Langfuse trace with deterministic score ids so redelivery overwrites rather than duplicates. It never touches the incident path, and a verdict never changes how an incident is handled.

**Tech Stack:** Python 3.12, aiokafka, langfuse 3.15.0 SDK, langchain 1.4.2 / langchain-openai 1.6.4 through the LiteLLM gateway, structlog, pytest.

**Spec:** `docs/superpowers/specs/2026-09-23-llm-judge-design.md`

## Facts already verified — do not re-investigate

Checked against the running stack and this repo's `.venv` before the plan was written.

- **A score with only `session_id` and no `trace_id` is accepted by the SDK and silently dropped by the server.** Scores must carry a `trace_id`. This is why scores target the incident's first trace.
- **A score on a trace id that does not exist is also silently dropped.** An untraced incident cannot be scored; only the audit row survives.
- **A repeated `score_id` upserts.** Writing the same id twice leaves one row carrying the second value and comment.
- **`BOOLEAN`, `NUMERIC` and `CATEGORICAL` all store on a trace.** A CATEGORICAL score's string lands in `stringValue` with `value` set to `0`; BOOLEAN takes `1`/`0`.
- `trace_id_for(incident_id, event_id)` is already in `telemetry.py` and is a pure function.
- Evidence items in graph state are **dicts**, not models: `{evidence_id, tool, observation, observed_at, trusted, simulated}`.
- `store.get_state(incident_id)` returns the final state dict; `store.audit(incident_id, kind, detail)` writes an audit row and does not depend on Langfuse.
- The graph emits exactly two terminal events, `incident.resolved` and `incident.manual_review`. `denied` emits nothing.
- The Langfuse ingestion worker does not recover its Redis connections after the host sleeps. If scores seem not to arrive, check `docker compose logs langfuse-worker` for socket timeouts and restart it before concluding anything.

## Interaction with the evidence-summarisation feature

`main` gained `feat: bound analyst context with evidence summarization` (`573c80d`) after this
plan was written. It can replace an evidence item's `observation` with a model-generated summary
marked `context_representation: "llm_summary_not_original"`, which would matter a great deal to a
judge assessing whether an RCA follows from its evidence.

**It does not affect this feature, verified by reading the code:**

- `build_context` pins RCA-cited evidence: `context.py:167` skips compression for any
  `evidence_id` in the RCA's `evidence_ids`. The evidence this judge reads is the cited evidence,
  so it is verbatim by construction.
- `build_context` operates on a deepcopy view and is called only from `Analyst.structured`
  (`llm.py:105`). Its result is never written back to state, so `store.get_state` returns
  authoritative, uncompressed evidence regardless.

Two consequences for the implementer. Do not add summary-awareness to the judge prompt; it would
describe a case that cannot occur. And if a future change ever unpins cited evidence or persists
a compressed view, this judge silently starts assessing summaries instead of observations — worth
a comment at the `cited_evidence` call site, which Task 5 includes.

```python
"""Pure scoring helpers for the judge service.

Deterministic scores restate facts the workflow already produced. A score whose source is
absent is omitted rather than defaulted: a missing score and a false score mean different
things, and recording the second for the first would corrupt every aggregate over it.
"""

from typing import NamedTuple
from uuid import NAMESPACE_URL, uuid5

VERDICT_VALUES = {"supported": 1.0, "partially_supported": 0.5, "unsupported": 0.0}


class Score(NamedTuple):
    name: str
    value: float | str
    data_type: str
    comment: str = ""


def score_id_for(incident_id: str, name: str) -> str:
    """Derive a score's identity so a redelivered event overwrites instead of duplicating."""
    return str(uuid5(NAMESPACE_URL, f"score:{incident_id}:{name}"))


def verdict_value(label: str) -> float:
    return VERDICT_VALUES[label]


def deterministic_scores(state: dict) -> list[Score]:
    scores = []
    if "verified" in state:
        scores.append(Score("outcome_verified", int(bool(state["verified"])), "BOOLEAN"))
    if "status" in state:
        scores.append(Score("outcome_status", state["status"], "CATEGORICAL"))
    if "rounds" in state:
        scores.append(Score("investigation_rounds", state["rounds"], "NUMERIC"))
    if "rca_valid" in state:
        scores.append(Score("rca_citations_valid", int(bool(state["rca_valid"])), "BOOLEAN"))
    return scores


def cited_evidence(state: dict) -> list[dict]:
    """Only the evidence the RCA actually cites.

    Uncited evidence is irrelevant to whether the stated conclusion follows, and passing it
    would ask the judge a different question.
    """
    cited = set((state.get("rca") or {}).get("evidence_ids") or [])
    return [e for e in state.get("evidence") or [] if e.get("evidence_id") in cited]
```

```python
class Judge:
    """Scores whether an RCA follows from its cited evidence.

    Takes primitives rather than graph state, so this module stays free of state-shape
    knowledge and the cited-evidence filter can be tested as a pure function elsewhere.
    """

    def __init__(self, cfg):
        self.cfg = cfg
        self.model = _model(cfg, cfg.judge_model)

    async def faithfulness(self, hypothesis: str, confidence: float, cited: list[dict]) -> Verdict:
        prompt = ChatPromptTemplate.from_messages(
            [
                ("system", JUDGE_SYSTEM),
                (
                    "human",
                    "Hypothesis: {hypothesis}\nStated confidence: {confidence}\n"
                    "Cited observations: {cited}",
                ),
            ]
        )
        chain = prompt | self.model.with_structured_output(Verdict)
        return await chain.ainvoke(
            {
                "hypothesis": hypothesis,
                "confidence": confidence,
                "cited": json.dumps(cited),
            }
        )
```

### Task 5: The consumer service

> **Upsert semantics to be aware of here.** Verified against a live server during Task 3:
> `create_score` replaces the whole row, not just the value — a second write with the same
> `score_id` overwrites the earlier comment as well. Consequences for this task, none of which
> need code beyond what is specified below:
>
> - A redelivered terminal event re-judges, so `rca_faithfulness`'s comment may change between
>   deliveries if the model words its reason differently. That is re-judging working, not drift.
> - If the judge call *fails* on a redelivery having succeeded earlier, the four deterministic
>   scores are rewritten and `rca_faithfulness` is simply not written — so the earlier verdict
>   survives rather than being blanked. That is the desirable outcome and falls out of the
>   specified control flow; do not "fix" it by writing a placeholder score.

```python
"""Score completed incidents from terminal domain events.

Runs as its own service with its own consumer group, so judging never touches the incident
path. Scores attach to the incident's first trace, because a score naming only a session is
silently dropped by the server. Verdicts are observational: nothing here changes an incident.
"""

import asyncio

import structlog
from aiokafka import AIOKafkaConsumer

from incident_platform.config import settings
from incident_platform.integrations.evaluation import record_score
from incident_platform.integrations.llm import Judge
from incident_platform.judge.scoring import (
    Score,
    cited_evidence,
    deterministic_scores,
    score_id_for,
    verdict_value,
)
from incident_platform.models import Envelope
from incident_platform.storage import Store
from incident_platform.telemetry import configure_logging, init_tracing, trace_id_for

log = structlog.get_logger()
TERMINAL_TOPICS = ("incident.resolved", "incident.manual_review")


async def judge_incident(store, judge, incident_id: str):
    state = await store.get_state(incident_id)
    if not state:
        # The outbox can outrun a state write; nothing to score, and nothing to retry.
        await store.audit(incident_id, "judge.state_missing", {})
        return
    scores = deterministic_scores(state)
    rca = state.get("rca") or {}
    verdict = None
    if rca:
        try:
            verdict = await judge.faithfulness(
                rca.get("hypothesis", ""), rca.get("confidence", 0.0), cited_evidence(state)
            )
            scores.append(
                Score(
                    "rca_faithfulness",
                    verdict_value(verdict.label),
                    "NUMERIC",
                    f"{verdict.label}: {verdict.reason}",
                )
            )
        except Exception as exc:
            # Losing four free scores because one model call failed would be the wrong trade.
            log.warning("judge.unavailable", incident_id=incident_id, error_type=type(exc).__name__)
    event_id = state.get("input_event_id")
    if event_id:
        trace_id = trace_id_for(incident_id, event_id)
        for score in scores:
            record_score(
                trace_id=trace_id,
                name=score.name,
                value=score.value,
                comment=score.comment,
                score_id=score_id_for(incident_id, score.name),
                data_type=score.data_type,
            )
    else:
        log.warning("judge.untraceable", incident_id=incident_id)
    await store.audit(
        incident_id,
        "judge.verdict",
        {
            "scores": {score.name: score.value for score in scores},
            "faithfulness": verdict.label if verdict else None,
            "reason": verdict.reason if verdict else None,
            "rca_present": bool(rca),
        },
    )


async def consume(store, judge, cfg):
    while True:
        consumer = AIOKafkaConsumer(
            *TERMINAL_TOPICS,
            bootstrap_servers=cfg.kafka_bootstrap_servers,
            group_id="incident-judge-v1",
            enable_auto_commit=False,
            auto_offset_reset="earliest",
            max_poll_records=1,
        )
        try:
            await consumer.start()
            async for message in consumer:
                event = Envelope.model_validate_json(message.value)
                await judge_incident(store, judge, str(event.incident_id))
                # Commit last: a redelivery overwrites the same scores by their derived ids.
                await consumer.commit()
        except Exception as exc:
            log.warning("judge.retry", error_type=type(exc).__name__)
            await asyncio.sleep(2)
        finally:
            await consumer.stop()


async def main():
    configure_logging()
    cfg = settings()
    init_tracing(cfg)
    store = Store(cfg.database_url)
    await store.open()
    try:
        await consume(store, Judge(cfg), cfg)
    finally:
        await store.close()


if __name__ == "__main__":
    asyncio.run(main())
```

## Follow-ups outside this plan

Surfaced by review during implementation, deliberately not done here:

- **`telemetry.trace_id_for` has the same boundary collision** that Task 1's `score_id_for` was
  hardened against: it seeds `f"{incident_id}:{event_id}"`, so ambiguous argument pairs collide.
  Unreachable today because both arguments are UUIDs. It is already merged to `main` as part of
  the tracing feature, so it belongs in its own change, not in this diff.
- **`data_type` is a free string** in both `record_score` and `Score.data_type`, where the SDK
  accepts only `NUMERIC`, `CATEGORICAL`, `BOOLEAN` and `TEXT`. A `Literal` would catch a typo in
  an editor, though this project runs no type checker in CI, so it buys hinting rather than a
  guarantee. Both must change together: narrowing only one produces a type error at the single
  call site, which is worse than narrowing neither.

## Out of scope

Named so they are not quietly added:

- Offline dataset runs and `evals/cases.jsonl`. The next cycle.
- Injection resistance, evidence sufficiency and plan proportionality as rubric dimensions.
- Any domain event, state change or re-opening driven by a verdict.
- Judging `denied` incidents; that node emits no domain event.
- Dashboards, thresholds or alerting on scores.
- A durable inbox for the judge. The derived `score_id` makes results idempotent; a duplicated
  terminal event costs one extra model call, which is accepted.
